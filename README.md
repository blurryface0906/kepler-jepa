## Контракт данных

- `generate_kepler_analytical(a, e, t, ...)`: `(N,1)`, `(N,1)`, `(1,T)` →
  `(N,T,4)`, каналы `[rx, ry, vx, vy]`, `float64`. Восемь итераций Ньютона;
  при отсутствии сходимости для `e` около единицы применяется документированный
  резервный метод бисекции. В рабочем диапазоне `e∈[0.2,0.6]` он не нужен.
- `integrate_verlet(r0, v0, T_steps, ...)`: `(N,T_steps,4)`, `float64`.
  Нулевой отсчет — переданное начальное состояние, затем `T_steps-1` шагов.
  Опциональный `substeps=1` сохраняет прежнее поведение; при `substeps=5`
  между сохраненными отсчетами выполняются пять шагов длины `dt/5`.
  Смягчения потенциала нет.
- `compute_orbital_invariants`: ряды `energy`, `angular_momentum`, `a_eff`
  формы `(N,T)` и максимальные относительные дрейфы `energy_drift`,
  `angular_momentum_drift` формы `(N,)`. При нулевом начальном инварианте
  его относительный дрейф не определен.
- Круговые, обучающие эллиптические и контрфактические выборки — словари
  `{"trajectories": ..., "meta": ..., "dt": 0.01, "split": ...}`.
  `meta` содержит массивы параметров формы `(N,)`.
- Тестовые эллипсы — словарь из двух таких выборок:
  `perihelion_init` и `aphelion_init`, с совпадающими `a`, `e`, `omega_arg`.
  Центр четного окна `L=16` находится между отсчетами 7 и 8, при `t=0.075`;
  именно туда приходится апсида непрерывного решения.
- ID-тестовая сетка сдвинута на половину шага обучающей логарифмической
  сетки от обеих границ. Радиусы train/test_id не совпадают.
- У контрфактических орбит `meta['a']` и `initial_radius` обозначают
  **начальный радиус**. Фактическая большая полуось записана в `a_true`.

Пример получения окон:

```python
from src.dataset import build_dataset_circ, KeplerWindowDataset

batch = build_dataset_circ("train", seed=42)
dataset = KeplerWindowDataset(batch["trajectories"], L=16, H=128,
                              channels=4, meta=batch["meta"])
context, targets, meta = dataset[0]
# context: (16,4), targets: (128,16,4), оба torch.float32
# targets[k-1] начинается на k отсчетов позже context, k=1..128.
```

Окна никогда не пересекают границы орбит. Большой массив всех целевых
окон заранее не создается. Целевые окна при малых сдвигах перекрываются
с контекстом по определению Task 1; в будущих экспериментах это необходимо
учитывать при интерпретации предсказательной задачи.

## Спектральный протокол

`project_to_2d_mode` явно центрирует ряд и делает PCA через SVD. Для двух
каналов выполняется только центрирование. Частотные функции принимают
двухканальный `U`; для `d>2` они автоматически вызывают эту проекцию.

S1 и S2 удаляют среднее перед FFT. S2 обнуляет DC и интерполирует логарифм
мощности трех соседних бинов. S3a реализует разрешенный ТЗ точный двумерный
оператор перехода, без Hankel-расширения. S3b регрессирует развернутую фазу.
Для двухканального входа S3a/S3b сохраняют переданное начало координат.
Это позволяет явно сравнивать физическую фазу относительно центра силы
с фазой после центрирования короткой дуги. Никаких поправок по истинному
периоду или параметрам орбиты оценщики не используют.

Аргумент `use_differences=True` у S3a/S3b применяет `np.diff(U, axis=0)`
перед оцениванием; среднее из разностей повторно не вычитается. Разностный
DMD сохраняет частоту невырожденной линейной гармонической моды; точная
разностная фаза дополнительно требует сохранения круговой геометрии.
Поэтому результаты произвольного нелинейного энкодера проверяются эмпирически.

## Модели и Эксперимент №1

`SequenceEncoder` поддерживает `linear`, `mlp`, `transformer`.
`M0_RandomJEPA` замораживает энкодер и предиктор, `M1_IJEPA1D` содержит
EMA-таргет, `M2_JEPA_OPF` использует четыре блока латентных координат
(в архивной архитектуре — независимые факторные предикторы),
`M3_IJEPA_SIGReg` добавляет заданный ТЗ штраф на среднее и
ковариацию. Это управляемые одномерные варианты из ТЗ; полный пайплайн
оригинальных статей не воспроизводится. Заданный моментный штраф M3
отличается от полного алгоритма SIGReg в LeJEPA.

Модели по умолчанию используют `torch.float32`; для Эксперимента №1 слои
создаются и ортогонально инициализируются непосредственно в `torch.float64`.
Все модели предоставляют `encode_sequence`, `rollout_autoregressive` и
`rollout_direct`. Вход роллаута `(B,d)`, выход `(B,steps,d)`, без начального
состояния. Градиенты сохраняются для обучения; при оценке нужны
`.eval()` и `torch.inference_mode()`. Архивный MLP-предиктор ограничен `H_max`;
ротационный предиктор Task 3.1 поддерживает произвольные положительные горизонты.

Эксперимент использует 30 радиусов из существующей сетки `test_id` в
`[0.5,2]`, пять seed, три энкодера, два окна `(256,4096)` и шесть
оценщиков. Веса проверяются хешами до и после прогона. Первая PCA
вычисляется для каждого окна отдельно; признаки и веса не обучаются.

```sh
python -m experiments.exp1_encoder_tautology --batch-size 512 --threads 4 --output reports/Task_3_1/exp1_recheck
```

Число потоков и размер батча регулируют выполнение, но не меняют состав
seed, моделей или орбит. JSON сохраняется после каждого прогона модели.
В нем записаны версии библиотек, SHA-256 исходников, параметры, оценки
каждой орбиты, сообщения неуспешных оценщиков и критерии приемки.
Высокая точность T1 сама по себе не доказывает выучивание динамики
предиктором и не устанавливает метод получения конкретного числа в статье.

Приемка нелинейных энкодеров в Task 3 уточнена без изменения данных, весов
и seed: один из методов `S3b_std` или `S3b_diff` должен одновременно пройти
пороги среднего по пяти seed (`mean(abs(slope+1.5)) < 0.005`,
`mean(SSE/SST) < 1e-5`) и худшего seed (`max(abs(slope+1.5)) < 0.005`,
`max(SSE/SST) < 1.5e-5`). Все отдельные результаты сохраняются.

Регрессия возвращает все поля из ТЗ и дополнительно `intercept`.
`one_minus_r2` вычисляется как `SSE/SST`, чтобы не терять малые остатки
из-за вычитания близких чисел. При постоянных частотах `R²` не определен.
При строго нулевом остатке `log10_one_minus_r2 = -inf`.

Определения библиотечных операций: [частотная сетка rFFT](https://numpy.org/doc/stable/reference/generated/numpy.fft.rfftfreq.html),
[развертка фазы](https://numpy.org/doc/stable/reference/generated/numpy.unwrap.html).

Этот раздел описывает архивный протокол Task 3. Для его воспроизведения
нужно распаковать `task3_original_sources.zip` в отдельную папку и выполнять

Для IDH используется CUDA-образ с уже установленным PyTorch и выделением
от 0.125 до 1 полной A100. Сначала проверяется доступность CUDA. Файл
`requirements-gpu.txt` устанавливает остальные зависимости и намеренно
не содержит `torch`, чтобы сохранить CUDA-сборку из образа IDH.

```sh
python -c "import torch; print(torch.__version__, torch.version.cuda); print(torch.cuda.is_available())"
python -m pip install -r requirements-gpu.txt
python -m experiments.exp2_circular_trained --preflight
python -m unittest discover -s tests -v
python -m experiments.exp1_encoder_tautology
python -m experiments.exp2_circular_trained --device cuda --resume
```

Перед полным запуском `--preflight` должен завершиться с `exit 0`; сведения
о GPU записываются в `reports/Task_3/gpu_preflight.json`. При недоступной CUDA
возвращается `exit 2`, обучение не подменяется CPU-прогоном. На IDH следует
использовать `requirements-gpu.txt`, а не переустанавливать PyTorch через
локальный `requirements.txt`.

Полный протокол фиксирован: seed `42 43 44 45 46`, три обучаемые модели
M1/M2/M3, по 2000 шагов, батч 256, MLP-энкодер с `d=64`, `L=16`, четыре
физических канала. Обучающая выборка содержит 200 круговых орбит
`a∈[0.5,5]`; ID-тест содержит 30 орбит в `[0.5,2]`, OOD-тест — 50 орбит
в `[0.25,0.45]∪[5.5,8]`. Необученная M0 оценивается отдельно.

Выбран разрешенный сдвиг `delta=4`, то есть макро-шаг равен `0.04`.
Direct-loss использует все горизонты `1..64`; AR-loss — 16 шагов замкнутого
роллаута и первые разности с весом 1. В первых разностях EMA-таргет включает
начальное состояние `k=0`. Квадрат L2-нормы суммируется по координатам и
усредняется по батчу и горизонтам. Для M1/M2 добавлен батчевый variance-barrier
на онлайн-состояния и онлайн-приращения с весом 0.1, для M2 — OPF-штраф
с весом 0.2; опциональная sparsity-регуляризация отключена.
OPF наследует из Task 2 стандартизованную ковариацию между факторами,
то есть межфакторную корреляцию; это конкретизация варианта M2.
AdamW использует `lr=1e-3`, `weight_decay=1e-4`, cosine decay до `1e-5`,
клиппинг градиентов 1.0 и линейный EMA-моментум `0.99→0.999`.

В T1/T2/T3 оцениваются 256 латентных состояний, в T4 — только обученные
горизонты `1..64`. Интервал между первым и последним состояниями составляет
соответственно **10.20** и **2.52** единицы времени; от начального контекста
до последнего предсказания T3/T4 проходит 10.24/2.56. Эти окна не покрывают
несколько полных периодов для всех радиусов: при `mu=1` период равен
`2πa^(3/2)` и растет с `a`. Ограничение коротких дуг, особенно для OOD,
учитывается при интерпретации частот и регрессий. Частота не корректируется
по истинным параметрам орбиты.

Для Task 3 у M3 включено `normalize_embeddings=True`: каждое отдельное
состояние энкодера, EMA-энкодера и предиктора центрируется по координатам
и нормируется на сферу радиуса `sqrt(d)` без обучаемого affine-преобразования.
Это дает единичный RMS координат, совместимый по масштабу с ковариацией `I`.
Центрирование координат ограничивает ранг ковариации величиной `d−1`,
поэтому точное равенство полной матрице `I_d` недостижимо.
Нормализация использует только текущее состояние; выбеливания по полной
траектории или будущим точкам нет. Loss M3 равен direct + AR + SIGReg
с весом 1, без variance-barrier M1/M2. Для прежних экспериментов этот режим
нормализации по умолчанию выключен.

Постоянная норма состояния M3 сама по себе не доказывает потерю масштаба
латентного цикла. Центрированный радиус зависит и от среднего траектории:
`R_cycle² = d - ||mean(Z)||²`. Поэтому проверяются отдельно регрессии по
радиусу цикла, норме состояния и механической энергии; H4 остается
эмпирической гипотезой до выполнения критериев на всех пяти seed.

Чекпойнты `reports/Task_3/checkpoints/M{1,2,3}_seed{seed}.pt` сохраняются
каждые 100 шагов и в конце обучения. Они содержат онлайн- и EMA-веса,
оптимизатор, scheduler, шаг, историю, все RNG-состояния, полную конфигурацию,
параметры модели, SHA-256 данных и исходников и сведения об окружении.
`--resume` включен по умолчанию: существующий совместимый чекпойнт
возобновляет тот же график обучения; несовпадающие протокол, seed, модель,
данные или исходники отклоняются. Изменение исходников во время эксперимента
также отклоняется. `--no-resume` начинает обучение заново; для независимого
нового запуска следует выбрать отдельную папку через `--output`.

Полный запуск записывает в `reports/Task_3`:

- `exp2_circular_stdout.txt` — stdout обучения и оценки;
- `exp2_circular_results.json` — полный результат, loss history и provenance;
- `exp2_circular_report.md` — таблицы всех методов и критериев;
- `figures/exp2_circular_regimes.png` — публикационный график, 300 dpi;
- `checkpoints/` — состояния обучения для возобновления.

Методы `S2`, `S3a_diff`, `S3b_diff`, `S3b_std` сообщаются все; основной метод
приемки заранее выбран как `S3b_diff`. Пороги проверяются по ID-выборке для
каждого seed; OOD сообщается как отдельная диагностика. Изменение основного
метода после просмотра результата не является независимой приемкой.

`execution_completed=true` означает, что все предусмотренные обучения
и оценки выполнены. `acceptance_passed=true` отдельно означает выполнение
научных порогов. Полный завершенный эксперимент может вернуть `exit 1`
из-за отрицательного научного результата; это не основание удалять seed,
подбирать веса или объявлять гипотезу подтвержденной. `exit 0` полного
прогона требует выполнения всех критериев. Ошибки обучения записываются
отдельно и не превращаются в успешные оценки.

Для проверки инженерной работоспособности разрешен отдельный короткий
CPU-smoke, который явно помечается и сохраняется в `reports/Task_3/smoke`:

```sh
python -m experiments.exp2_circular_trained --smoke-test
```

Его `exit 0` подтверждает только инженерное выполнение; он не заменяет
15 полных GPU-прогонов и не подтверждает научные критерии Task 3.

## Task 3.1: remediation Exp2

Полный прогон завершен; все 15 чекпойнтов сохранены локально в
`reports/Task_3_1/checkpoints/`. Контрольные суммы скачанного архива,
артефактов и исходников проверены; все 42 архивных файла Task 3 неизменны.
Чекпойнты исключены из Git. Для нового независимого запуска следует
указать отдельную папку через `--output`.

```sh
python -m unittest discover -s tests -v
python -m experiments.exp2_circular_trained --preflight
python -m experiments.exp2_circular_trained
```

Архивная команда Exp2 Task 3.1 запускает протокол `task3_1`: 15 CUDA-обучений по 2000
шагов с батчем 256, прежними AdamW/EMA и горизонтом обучения 64.
MLP-энкодер по умолчанию антисимметричен, с ортогональным линейным skip и
ветвью tanh с начальным gain 0.15. M1/M2/M3 используют обучаемый базис
`Q=exp(S−S.T)` и плоские повороты с частотами из сети `rate_net`.
Для M2 базис состоит из четырех блоков по 16 координат.

Новая потеря содержит точный относительный direct-член, прежний AR-член
с состояниями и скоростями и внутриорбитальный temporal-член с весом 1.
M2 сохраняет OPF с весом 0.2; M3 использует SIGReg с весом 1 без temporal.
Физические радиусы и формула закона Кеплера не подаются предиктору.

Обучение и чекпойнты используют float32. После сохранения весов все модели
явно переводятся в float64 для оценки численного дрейфа на 512 шагах.
T1/T2/T3 имеют 512 точек; T4 сообщается отдельно для 64 и 512 горизонтов.
Каждая проверка T4 требует выполнения порога в обоих вариантах.
Основная приемка фиксирована на полном d=64 и `S3b_diff`; ведущий фактор M2
выбирается по временной дисперсии и сообщается только как дополнительная диагностика.

H4 дополнена `phase_norm_r2`, `axis_probe_r2`, `state_norm_r2`; прежние
метрики сохранены. Для численно постоянной нормы явно применяется заданная
ТЗ конвенция нулевого R². Сохранение нормы не означает потери всей информации
о полуоси: скорость и направление могут сохранять ее после нормализации.
Сохранение нормы и согласованность T3/T4 заданы архитектурой; физические
частоты и выполнение регрессионных критериев устанавливаются экспериментом.

Архивные GELU/MLP варианты доступны через `mlp_variant="legacy_gelu"` и
`predictor_type="legacy_mlp"`; Exp1 явно использует прежний вариант энкодера.
Для воспроизведения всего старого Task 3 следует распаковать сохраненный
архив исходников в отдельную папку. Файлы `reports/Task_3/` не изменяются.
