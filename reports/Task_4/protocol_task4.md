# Task 4 — протокол до GPU-прогона

Источник требований: `Tasks/task_4_elliptic_kepler_and_invariants.md`. Научные ожидания из ТЗ проверяются как гипотезы, а не используются для отбора результатов. Пороговые значения, пять сидов 42–46 и четыре обучаемые модели фиксированы. При отрицательных результатах скрипт сохраняет все результаты и возвращает exit 1.

## Данные и доступная длительность

В каждой записи 2100 физических отсчётов с dt=0.01. Контекст 16, stride=4; T1/T3 оцениваются на 512 будущих точках. Пара peri/apo начинается в апсиде первым физическим отсчётом, не центром окна. Для ID используется исходная сетка 30 полуосей из кругового эксперимента. Стратифицированный e детерминированно переставлен: из 2048 перестановок по seed=49017 выбирается минимальная абсолютная корреляция e с log(a); используются только метки сетки, никогда модельные результаты. Остаточная корреляция сохраняется в JSON.

H=256 означает 10.24 единиц времени; период при a=5 равен примерно 70.25. Поэтому предположение ТЗ о полном цикле для всех орбит при этих длинах неверно. Два старта выбираются независимо из допустимых индексов одной записи, что также не гарантирует посещение обеих апсид для больших a. Длины и сетки из ТЗ сохраняются без скрытого расширения данных.

## Конкретизация обучения

- M1 Short: direct k=1..32 из одного старта, relative AR16 (состояния и приращения), временной барьер между этим стартом и lag16, штраф частот=0.
- M1 Inv / M2 Inv: direct k=8,16,...256 и relative AR16 усредняются по двум независимым стартам одной орбиты. Временной барьер использует два онлайн-представления; сопоставление log RMS относится к первому старту, как в формуле ТЗ. Штраф инвариантности суммируется по 32 частотам, затем усредняется по батчу; вес 2. M2 дополнительно использует mean OPF с весом 0.2, усреднённый по двум стартам.
- M3: та же парная длинная сетка, AR и инвариантность с весом 2, сферическая нормализация радиуса sqrt(64), SIGReg с весом 1. Временного штрафа масштаба нет. Это заранее объявленная конкретизация не полностью описанного функционала M3 в ТЗ.
- В Task 4 не применяются factor-scale и межплоскостная coherence из Task 3.2: эллиптическое представление может использовать разные гармоники. Остальные параметры оптимизатора и EMA наследуются из прежнего протокола.
- B256 у Inv означает 256 пар, у Short — 256 одиночных стартов. Одновременно меняются горизонт, число стартов и штраф инвариантности; сравнение не изолирует один из этих факторов.
- Ни a, ни e, ни энергия, ни истинная частота не поступают в функцию потерь.

## Оценивание и пробы

Все четыре прежних оценивателя S2/S3a_diff/S3b_diff/S3b_std сохраняются; основной T3 метод — S3b_diff. Для H3 допускается один фазовый метод, проходящий на всех пяти сидах данной модели; выбирать лучший метод отдельно для каждого сида нельзя. DMD сравнивается с S3b_std, как указано в ТЗ. Невалидные орбиты и отрицательные R² сохраняются. Средние не фильтруют неудачные сиды.

Пробы: StandardScaler и Ridge(alpha=.01), а также PolynomialFeatures(degree=2)+Ridge(.01), обучаются только на 200 орбитах train_ellip. Признаки — log RMS нормы, полный z0, все 32 log-частоты. Отбор почти постоянных столбцов (std<=1e-6) использует только train; полностью постоянная норма даёт пробу с одним свободным intercept. Все шесть целей (пять из ТЗ плюс log|E|) вычисляются для первого физического отсчёта контекста. Log|E| является аффинной функцией log a и не даёт независимого подтверждения энергии.

Критерий нормовой пробы применяется к M1 Inv, энергетический — к poly2 от log-частот M1 Inv, на ID, по каждому из пяти сидов. ТЗ содержит пять групп критериев; в JSON они развёрнуты в 12 отдельных PASS/FAIL. Сам факт завершения выполнения отделён от научной приёмки.

## Ограничения выводов

Нарушение фазовой инвариантности не доказывает единственную конкретную эвристику нормы. Хорошая проба энергии не доказывает её причинного использования предиктором. Равномерная окружность в латентном пространстве совместима с физическим эллипсом через переменную среднего движения. Топологический оборот фазы за полный цикл сам по себе не гарантирует несмещённую оценку частоты через линейную регрессию фазы на конечном окне. Все эти ограничения обсуждаются при интерпретации результатов без изменения критериев после прогона.

## Сохранность

Полный GPU-прогон фиксирует хеши всех Python-исходников src/experiments и requirements-gpu, проверяет их неизменность при завершении.
